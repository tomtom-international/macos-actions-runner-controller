## Why & what

> *Guidance:* The change, why it is needed, and what "done" looks like as a few plain testable bullets.

The controller (`internal/controller/server`) and tarter (`internal/tarter/api`, `cmd/tarter/app/server.go`) route HTTP with gorilla/mux. The scaler and metrics-aggregator already use the Go 1.22+ `net/http` ServeMux with method patterns (`internal/scaler/api/server.go:45`). This change moves controller and tarter to the same stdlib pattern, removes `github.com/gorilla/mux` from `go.mod` (`github.com/gorilla/websocket` stays), and gives all four servers one shared `pkg/core` layer for server construction, CORS, request logging and panic recovery.

The controller has two consumers: tarter's `pkg/clients/controller` client, and a browser SPA that uses the websocket and the GET endpoints. Its API contract, including CORS and the websocket origin check, must not change. Controller and tarter HTTP have no tests today, so pinning tests are written and made green against gorilla before any routing code changes, and they stay green unchanged afterwards.

## How - Program design

> *Guidance:* How we design the solution for the stated problem — a few sentences for a small change.

**Phase 1, seams and pins on gorilla.** First, make the code testable without changing routing.
- Controller: extract `NewHTTPServer(controller, address, port, origins) *http.Server` out of `ListenAndServeControllerServer` (`internal/controller/server/server.go:66-90`). `ListenAndServeControllerServer` then calls `NewHTTPServer(...).ListenAndServe()`. `NewServer(controller, origins) http.Handler` (`server.go:53`) stays the test seam over `ControllerInterface` (`server.go:36`).
- Tarter: replace the concrete handler dependencies with small interfaces in `internal/tarter/api/handlers`. The `/runners` handlers take a runner-store interface holding the `*state.StateManager` methods they call (`handlers.go:30,63,113`). The `/sys/*` handlers take a workers interface (`GetWorkersCount`, `ListRunnerWorkers`, `sys.go:28,52`). The standalone handlers take a standalone interface (`GetStandaloneConfig`, `RestartStandaloneRunners`, `standalone.go:28,52`).
- Tarter: extract the server build out of `Run` (`cmd/tarter/app/server.go:139-160`) into `newHTTPServer(port string, h http.Handler) *http.Server`.

Then write the pinning tests in `internal/controller/server/*_test.go`, `internal/tarter/api/routes_test.go` and `cmd/tarter/app/server_test.go`. They drive the real router through `httptest`, with testify fakes in the style of `internal/scaler/api/server_test.go:30-60`. Negative-case tests assert status codes and the headers listed above, not router-level 404/405 bodies. Those bodies may change to stdlib defaults, per the definition-of-done decision (LD-D-1). The method sweep leaves HEAD out, per the HEAD decision (LD-D-2). The contract test is an external `server_test` package. It points tarter's real client (`pkg/clients/controller/client.go:40`, `APIVersionPath: "/api/v1"`) at `httptest.NewServer(server.NewServer(fake, "*"))`, and it opens `/ws/watch` with a `gorilla/websocket` Dialer, because no client in the repo dials it (LD-D-9). The scaler and metrics-aggregator get server-config pins too (LD-D-11).

**Phase 2, the migration.** The controller routes (`internal/controller/server/routes.go:24-46`) become `http.ServeMux` patterns with the `/api/v1` prefix spelled out, for example `"PUT /api/v1/nodes/{node_uid}/status"`. `/ws/watch` stays outside the prefix. `.Methods("GET", "OPTIONS")` becomes two patterns, and `mux.Vars(r)["x"]` becomes `r.PathValue("x")` (`nodepool_handler.go:129,188,266`, `runners_handler.go:69,127`). `mux.CORSMethodMiddleware` (`server.go:62`) becomes a shared middleware that sets `Access-Control-Allow-Methods` to the value the pins captured, on the `/nodes` and `/runners` patterns only. The handlers keep setting `Access-Control-Allow-Origin` themselves (`nodepool_handler.go:33`, `runners_handler.go:33`), and the websocket `CheckOrigin` (`watcher_handler.go:33-47`) is untouched. Tarter moves the same way: `internal/tarter/api/routes.go:26-41` and `handlers.go:66,116`. `NewTarter` and `Run` (`cmd/tarter/app/server.go:105,139`) pass a `*http.ServeMux`, and the standalone routes are still registered before `ListenAndServe`. `SetupGenericHandlers`, `NotFoundHandler` and `MethodNotAllowedHandler` (`pkg/core/api/handlers.go:26-80`) are deleted, because nothing uses them after the migration (LD-D-14).

**Phase 3, the shared layer.** Add `pkg/core/api/server.go` with three helpers:
- `NewHTTPServer(addr string, h http.Handler, read, write, idle time.Duration) *http.Server`, which always sets `MaxHeaderBytes` to 1 MiB and leaves `ReadHeaderTimeout` unset.
- `AllowMethods(methods string, h http.Handler) http.Handler` for CORS.
- `Middleware(h http.Handler) http.Handler`. It recovers panics and returns 500, re-panicking `http.ErrAbortHandler`. It logs `method path status duration` through `logger.Debugf` (`pkg/logger`). Its status-recording `ResponseWriter` implements `http.Hijacker` and `Unwrap()`, so websocket upgrades still work.

All four servers build through `NewHTTPServer` and wrap their mux in `Middleware`: controller `server.go`, tarter `cmd/tarter/app/server.go`, scaler `internal/scaler/api/server.go:53`, metrics-aggregator `internal/metrics-aggregator/api/server.go:44`. Each keeps its own timeouts. Graceful shutdown and `ReadHeaderTimeout` stay out of scope (LD-D-13).
